# 再学習200epochの高域ノイズ比較

その後の[モデル内部の修正とアプリ登録更新](../retrained-repair-20261023/README.md)では、追加の通常文4本を含めた8文で検証し、再学習修正版をMacへ反映した。以下はそれ以前の原本比較・WAV後処理の履歴。

## 追加確認：学習再開の監査とノイズ除去

2026-10-23、本人から母音を伸ばした試験音声は歪むため使わないよう指定された。以後、この比較スクリプトの既定文から母音試験を除外する。下記5文の結果は指定前に行った検証の履歴であり、今後の4文比較と区別する。

180と再学習200の完全checkpointを直接読み、両optimizerの全状態（942件／106件）でstepが180000→200000、差が20000であることを確認。パラメータID順序とmomentum形状が一致し、終了側momentumに非有限値はない。schedulerは両方180→200、gamma=0.999875、学習率も連続している。保存ログの180／185／187／189からの4回の再開前検査はESPnet202211、torch1.12.1+cu113、47音素順序が共通で、optimizer失敗を示す行はない。唯一のTracebackは185終了後、平均化対象の180epochファイル不在によるもので、学習中のoptimizer復元失敗とは異なる。根拠はローカル `resume_audit.json`。再現は `tools/audit_resume_states.py`。

以前の181再開の実装変更・音素順序変更・optimizer復元失敗は別途確認済みだが、今回も同じ誤りが起きた証拠はない。ただし180時点の全依存パッケージとの完全一致までは検証できていない。追加学習で180より品質が悪くなった理由を、過学習や特定パッケージへ断定することもできない。

品質選定には問題が残る。既存のtrain/validは重なっており未知文の検証にならず、`best_model_criterion` は `train.total_count/max`、つまり学習回数である。bestというファイル名や正常終了を音質改善の根拠にはしない。200を180の上位版として採用する根拠はなく、180との通常文比較による選定が必要である。

依頼されたノイズ除去は、再学習200の通常文4本へFFmpeg `afftdn=nr=6:nf=-55:gs=10` を適用した。元WAVとモデルは保持。FFTフィルターの遅延1102サンプルは末尾を事前にパディングして補正し、相互相関のずれ0、サンプル数一致、44.1kHz/16bit/mono、クリップ0を確認。時間伸縮は使っていない。300〜4000Hzエネルギー変化は−0.013〜−0.007dB、8〜20kHzは−1.59〜−0.79dB。ただし高域エネルギーには子音も含まれ、ノイズだけの減少量ではない。周期ピーク指標は本人文0.414→0.336、旅行文0.511→0.613、摩擦音文0.188→0.359、博士の文0.731→0.671dBと増減がある。完全除去や声質維持の聴感検証済みとは主張しない。

成果物は同じローカル出力の `denoised/`。各文の `*_before_after.wav` は処理前→処理後、1秒間隔。各区間を線形ゲインだけで−23LUFSに揃え、実測−23.01〜−22.99LUFS、true peak最大−4.84dBTP。`verification.json` に検証結果、`tools/denoise_comparison.py` に再現処理を保存。COEIROINK登録モデルと公開ZIPは置換していない。

## 指定前の5文比較

2026-10-23。再学習200epochでは、以前の200epochで増えていた約689Hz間隔の高域周期ピークが、比較した5文すべてで低下した。180epochに近づいたが、完全に同じ水準へ戻ったとは言えない。

| 比較文 | 180原本 | 以前の200原本 | 再学習200 |
|---|---:|---:|---:|
| 母音・天気 | 0.51 | 2.65 | 0.98 |
| 「迷惑かけちゃって…なかったんだよ」 | 0.24 | 2.93 | 0.41 |
| 東京から京都への旅行 | 0.27 | 3.06 | 0.51 |
| 摩擦音を含む文章 | 0.09 | 2.91 | 0.19 |
| 「でも、このまま博士が…」 | −0.16 | 2.69 | 0.73 |
| 5文平均 | **0.19** | **2.85** | **0.56** |

単位はdB。母音中央区間のスペクトルについて、44100/64=689.0625Hzの10〜26倍に当たる17本の周波数を調べ、周辺周波数に対する突出度を平均した既存の指標を使った。ノイズ量、SNR、聴感上の改善率を表す値ではない。負値は対象周波数が周辺より弱いことを示す。

3dBを超える周期ピークの本数は、以前の200が各文5〜8本、再学習200が母音文2本・ほか4文0本、180が母音文1本・ほか4文0本。再学習版でも母音文などには残留がある。8〜20kHz全体のエネルギー比は文章により変わり、周期ピーク指標と同じ意味には扱わない。高域を一律に削った結果とは区別する。

## 条件と検証

- 同じ隔離COEIROINKエンジン、CPU、speedScale=1、同じ5文で3モデルを新規生成。アプリ登録中のモデルは変更していない。
- 180と以前の200は無加工原本。以前作った音量校正版・高域補正版は使っていない。各モデルに対応する音素順序を使い、再学習版は180の47音素順序を維持。
- 再学習200は終了時の完全checkpoint（reporter epoch200、optimizer状態942/106、scheduler last_epoch200）と1049テンソルすべて一致。SHA256はmanifest.jsonに保存。
- 15音声すべて44.1kHz／16bit／mono、有限・非無音、PCMクリップ0。問題の文章を3モデルで各1回追加生成し、元の生成波形と完全一致。
- 分析は未加工WAVで実施。聴き比べ用だけ線形ゲインで−23 LUFSへ調整し、書き出し後のLUFS・true peak・PCMクリップを検査。EQ、フィルター、ノイズ除去、コンプレッサー、時間伸縮は使っていない。

## 聴き比べ音声

ローカル成果物 `output/talk_full_20260917/retrain_comparison_20261023/` に保存。

- `raw/`：未加工の15音声と生成条件・音素時間情報。
- `listening/`：音量を揃えた個別15音声、および5文の連続比較。
- `listening/user_180_old200_retrained200.wav`：本人指定文。180 → 以前の200 → 再学習200、間隔は各1秒。
- `listening/vowels_180_old200_retrained200.wav`：母音比較。同じ順序。
- `results.json`：スペクトル・測定値。`listening_levels.json`：調整前後LUFS、true peak。
- `checkpoint_verification.json`、`repeatability.json`：モデル照合と再生成一致の検証。

発音・声質の好みや任意の文章での品質は、この測定だけでは確定できない。聴き比べ用音声を添え、周期ノイズが数値上改善したという結論と分ける。今回の比較から学習環境・音素対応・optimizer復元の各要因の寄与までは分離できない。既存のCOEIROINK登録・公開ZIPは置き換えていない。

再現スクリプト：`tools/retrain_noise_compare.py`。`prepare`、`generate`、`listening`の順に実行。既存の隔離エンジン（port50033）と原本モデルを必要とする。途中生成物がある場合は再利用するため、条件を変える際は新しい出力先を指定する。
