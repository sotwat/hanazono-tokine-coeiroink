# 再学習200の周期ノイズ修正とアプリ登録の更新

2026-10-23。再学習200の波形生成器へ位相応答の補正を施し、通常文8本すべてで対象の高域周期ピークが低下した。MacのCOEIROINKに残っていた旧200補正版を退避し、モデルと音素設定を再学習修正版へ更新した。スタイル名は **200epoch（再学習修正）**、styleId=1200。実画面で選択・指定文の生成・再生を確認し、アプリ側エンジンの実出力4本が検証用モデルとPCM完全一致した。

## 切り分けで分かったこと

旧200と今回の再学習200は別物である。更新前の登録モデルのSHA256 `ede96bb765fe066a47c7117f8dcd324c125761dc891b1070c628c6079282e031` は、以前の200へ音量校正・高域補正を加えたモデルと完全一致し、47音素も旧181〜200の順序だった。旧モデルと旧設定の組は整合していたが、再学習版をアプリへ反映した状態ではなかった。アプリでの200試聴と、前回渡した再学習200のWAVを混同しない。この反映漏れだけで、本人がどの音源で感じた劣化かまで説明できるとはしない。

再学習200の原本に対しては、180との双方向decoder交換、第2拡大層の双方向交換、同層と後続residual blockの交換、text encoder／flow／duration predictorの交換、位相応答補正を実施した。13モデル構成、切り分け4文52WAVと、補正量の選択に使っていない追加4文×3モデル12WAV、計64WAVを検査した。母音の引き伸ばしは使っていない。

decoderを180へ全交換した場合の周期ピーク指標は、再学習200から本人文0.414→0.379、旅行文0.511→0.054、摩擦音文0.188→0.310、博士の文0.731→0.834dBと増減した。逆方向の交換でも変化が一定でない。以前の200で確認した「decoderの交換で大幅改善」という結果を、再学習200へそのまま適用することはできない。今回の差は追加学習で変化した内部特徴とdecoderの組み合わせに依存し、一つの層の差分だけを唯一の劣化原因とは扱わない。

一方、第2拡大層の8位相間DC応答差を減らす介入は、今回の8文すべてで約689.0625Hz間隔の高域周期ピークを下げた。発音を作る重みと音素時間を維持したまま、この周期成分を抑えられる箇所を確認できた。無音の内部入力によるdecoder単独試験でも、採用補正で周期AC RMSは0.007006→0.004471、高域の周期パワーは1.6975→1.0071へ下がった。ただし無音入力時の高域パワーは180より未補正200の方が低い。したがって「200のdecoderはあらゆる入力で180よりノイズが多い」とは言えない。

学習履歴の監査は[前回の報告](../retrain-comparison-20261023/README.md)を参照。今回の再学習ではoptimizer初期化の再発を示す証拠はない。train/valid重複とbest判定が学習回数である点は品質選定の欠陥だが、それ自体が重みを壊した原因だと証明したわけではない。特定の学習率・過学習・パッケージ変更を歴史的原因として断定する対照再学習実験は行っていない。

## 採用した修正と検証

第2拡大層の各位相の応答を平均へ半分だけ近づけた。変更はweight_vとweight_gの2テンソル、他1047テンソルは保存後に原本と完全一致。対象層の実効重み変化は26.21%あり、変更数だけを理由に微小な修正とは呼ばない。学習用checkpointを作り直したものではなく、再学習200の推論専用派生モデルである。学習再開に使わない。

単位dB。母音中央区間の約689Hz第10〜26倍、17周波数の周辺に対する突出度であり、ノイズ量・SNR・総合音質ではない。修正版は8文すべてで再学習200より低く、180より低いのは6文。負値は中心周波数が周辺より弱いという意味で、無雑音ではない。

全8文で、修正前後のサンプル数とmoraDurationsが完全一致。本人文の語尾「よ」も両者0.20898秒で、伸縮していない。波形相関は0.9912〜0.9977。Whisper-smallの認識結果は、空白・句読点を除いて修正前後8文すべて一致。ただし旅行文の「切符」は両方で正しく認識されず、認識一致を発音の完全性の証明には使わない。声質の自然さを聴感確認済みとも主張しない。

比較用24音声は線形ゲインだけで−23LUFSに合わせ、実測−23.02〜−22.99LUFS、true peak最大−4.22dBTP。全64生成音声は44.1kHz/16bit/mono、非無音、PCMクリップ0。採用モデルの生成音声には、EQ・ローパス・afftdn・時間伸縮を適用していない。前回のWAV後処理とは別の修正である。
